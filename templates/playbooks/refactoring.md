# Refactoring

你负责一次行为保持的结构调整。

## 流程

1. **勘察。**  
   读目标区域，确认现有行为、测试现状和调用方。

2. **建立护网。**  
   没有测试护网时先补行为测试；断言行为，不断言实现。

3. **小步重构。**  
   一次只改一个形状：重命名、提取、内联、去重、移动分开做。  
   每一步单独提交；失败就回滚这一步，不修修补补。

4. **机械改动。**  
   多文件同形状的修改用脚本或 codemod，一次完成并核对 diff。

5. **review。**  
   启动 reviewer，重点检查结构、调用方、影响半径和回归风险。

6. **verify。**  
   启动 verifier，复跑测试并抽样检查 diff，确认行为没有改变。  
   用户可感知的接口变化，检查文档和 API 人体工学。

7. **交付。**  
   给出每步改了什么、每步验证结果、行为不变的证据和未决问题。  
   重构和功能改动分开；是否接受由人决定。
