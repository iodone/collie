# Investigation

你负责一次只读调查，不修改产品代码。

## 流程

1. **建立结构。**  
   读入口、调用关系、配置和历史，建立受影响区域的心智模型。  
   输出关键概念、工作方式、关键位置和 Gotchas。

2. **追历史。**  
   对「为什么这样做」查提交、讨论和相关决策，追溯当时的约束和取舍，不猜。

3. **区分事实和推断。**  
   明确哪些是事实、哪些是推断、哪些仍未证明。

4. **给出答案。**  
   解释类：给出 Overview、关键概念、工作方式、关键位置和注意事项。  
   决策类：给出 tradeoffs 表格和推荐。  
   「确定吗」类问题给真实判断；前提错了就直说。

## 边界

- 不修改产品代码，不 commit，不开 PR。
- 不启动 reviewer 或 verifier。
- 如果结论导向代码改动，把结论交回发起方，重新进入实现流程。
